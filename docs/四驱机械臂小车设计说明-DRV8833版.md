## 1 方案差异与设计取舍

DRV8833 版与 TB6612 版共用同一套上层逻辑：PS2 手柄、三路舵机、上电即可行驶、松手制动、失联保护都不变。差异集中在电机驱动层：TB6612 每个电机是"1 路 PWM + 2 个方向脚"，DRV8833 每个电机是"2 路 PWM（IN1/IN2）"。

**表 1-1 两个版本的差异**

| 项目 | TB6612 版 | DRV8833 版 |
| --- | --- | --- |
| 每电机引脚 | 1 路 PWM + 2 方向 | 2 路 PWM（IN1/IN2） |
| 驱动使能 | STBY × 2 | nSLEEP × 2 |
| 电机 PWM | TIM2 CH1~4 | TIM2 CH1~4 + TIM1 CH1~4 |
| 调试串口 | USART1（PA9/PA10） | USART3（PB10/PB11） |
| 电池 | 2S / 3S | 仅 2S |
| 刹车 | IN1=IN2=1 | IN1=IN2=1（两路 PWM 都输出 100%） |

### 1.1 为什么每个电机要两路 PWM

DRV8833 没有独立的 PWM 引脚，速度由 IN1、IN2 的平均电压决定。要同时支持正转、反转和调速，两路输入都必须能输出 PWM：

- 正转：IN1 输出 PWM，IN2 保持 0；
- 反转：IN1 保持 0，IN2 输出 PWM；
- 刹车：IN1、IN2 都输出 100%，两个下管同时导通，绕组短接；
- 滑行：IN1、IN2 都输出 0，输出高阻。

如果只给一路 PWM、另一路用普通 GPIO，反转时只能全速，无法调速；所以这版用 TIM2 的 4 个通道驱动四路 IN1，再用 TIM1 的 4 个通道驱动四路 IN2，两个定时器都是 20 kHz、3600 级分辨率。

### 1.2 为什么只能 2S

DRV8833 的 VM 额定范围是 2.7~10.8 V。2S 锂电满电 8.4 V，安全；3S 满电 12.6 V 会超过绝对上限，可能直接损坏芯片。因此本版电源、电机选型都按 2S 设计，不能用 TB6612 版的 3S 方案。

> **选型提醒**：DRV8833 每通道连续 1.2 A、峰值 2 A。四个电机同时堵转可能超过芯片能力，建议选堵转电流 ≤1.2 A 的电机，并在调试时限制最大占空比。

### 1.3 调试串口为什么换到 USART3

TIM1 的 CH1~CH4 占用 PA8~PA11，其中 PA9、PA10 原本是 USART1 的 TX/RX。为了不牺牲任何一路电机 PWM，调试串口改到 USART3 的 PB10/PB11；PS2、舵机、LED、SWD 的引脚都保持不变。

### 2.4 电源与保护

- 电池：2S 锂电（7.4 V，满电 8.4 V），容量建议 ≥2000 mAh、放电 ≥20C。
- 保险：总回路 10 A；VM 入口并 1000 µF 电解 + 0.1 µF 瓷片。
- 舵机：仍然使用独立 5 V/5 A 模块，不能从主控 3.3 V 取电。
- 共地：电池、两片 DRV8833、5 V 模块、主控 GND 必须单点汇接。
- nSLEEP：不能悬空，代码上电默认拉低，进入可行驶状态后拉高；调试时若电机不转，先量 PB3/PB9。

> **不要接 3S**：DRV8833 的 VM 绝对上限是 10.8 V。3S 满电 12.6 V 会超限，轻则保护、重则永久损坏。本版电源、电机、参数都按 2S 选型。

## 3 STM32CubeMX 配置

外设配置与 TB6612 版大部分相同，差别是：TIM1 也要开 4 路 PWM，USART1 改成 USART3。

### 3.1 时钟

HSE 8 MHz → PLL ×9 → SYSCLK 72 MHz；AHB /1、APB1 /2（36 MHz）、APB2 /1（72 MHz），Flash Latency 2 WS。与 TB6612 版完全一致。

### 3.2 GPIO

**表 3-1 GPIO 配置**

| 引脚 | 模式 | 初始电平 | 用途 |
| --- | --- | --- | --- |
| PA4 | Output Push Pull | High | PS2 片选 |
| PB3 | Output Push Pull | Low | DRV8833 #1 nSLEEP |
| PB9 | Output Push Pull | Low | DRV8833 #2 nSLEEP |
| PC13 | Output Push Pull | High | LED（低亮） |

SYS → Debug 必须选 Serial Wire：PB3 默认是 JTDO，不关 JTAG 就不能当 GPIO 用。

### 3.3 TIM1 与 TIM2（各 4 路电机 PWM）

两个定时器参数完全一样，都是 20 kHz、3600 级分辨率。

**表 3-2 TIM1 / TIM2 配置**

| 参数 | 值 | 说明 |
| --- | --- | --- |
| Clock Source | Internal Clock | — |
| Channel1~4 | PWM Generation CHx | TIM1 → PA8~PA11；TIM2 → PA0~PA3 |
| Prescaler | 0 | 72 MHz |
| Counter Period (ARR) | 3599 | 72 MHz ÷ 3600 = 20 kHz |
| Counter Mode | Up | — |
| auto-reload preload | Enable | — |
| PWM Mode | PWM mode 1 | — |
| Pulse | 0 | 上电 0% 占空比 |
| Output compare preload | Enable | — |
| CH Polarity | High | — |

### 3.4 TIM4（三路舵机）

与 TB6612 版相同：PSC 71、ARR 19999、CH1~CH3 PWM、Pulse 1500、引脚 PB6/PB7/PB8，得到 1 µs 计数、20 ms 周期、50 Hz。

### 3.5 SPI1（PS2）

Full-Duplex Master、8 bit、MSB、256 分频、CPOL High、CPHA 2 Edge、NSS Software、CRC Disabled；PA4 单独做 GPIO 片选，约 281.25 kHz。

### 3.6 USART3（调试）

Asynchronous、115200、8N1、无流控，引脚 PB10（TX）/PB11（RX）。

### 3.7 生成与接入

Project Manager 中 Toolchain 选 STM32CubeIDE，取消勾选"Generate peripheral initialization as a pair of .c/.h files per peripheral"，勾选 Keep User Code；生成后把本目录的 Core/Inc、Core/Src 复制进去，并用本目录 main.c 覆盖生成的 main.c。

> **重复定义**：若编译提示 MX_TIM1_Init 等重复，说明生成时勾选了外设 .c/.h 分离，删除 tim.c/spi.c/usart.c/gpio.c 即可。main.c 中的 4 个 MSP 函数已定义为 __weak，与 stm32f1xx_hal_msp.c 同名函数不会冲突。

### 4.2 双 PWM 驱动实现

Motor_SetDuty() 把带符号占空比翻译成两路 CCR：正转时 IN1 输出占空比、IN2 置 0；反转时反过来；0 时两路都置 0。CCR 按 ARR 自动缩放。

**代码 4-1 两路 PWM 的正反转映射**

```c
void Motor_SetDuty(MotorId id, int16_t duty)
{
    if (s_hw[id].invert) duty = -duty;
    if (duty > 1000)  duty = 1000;
    if (duty < -1000) duty = -1000;
    Motor_Enable();
    if (duty > 0)      WriteCcr(id, DutyToCcr(period_a, duty), 0);
    else if (duty < 0) WriteCcr(id, 0, DutyToCcr(period_b, -duty));
    else               WriteCcr(id, 0, 0);   /* 滑行 */
}
```

### 4.3 刹车、滑行与休眠

**表 4-2 三种停机方式**

| 动作 | IN1 / IN2 | 实现 | 场景 |
| --- | --- | --- | --- |
| 滑行 | 0 / 0 | 两路 CCR = 0 | 待命、松杆后保压结束 |
| 短接制动 | 1 / 1 | 两路 CCR = ARR + 1（100%） | 松杆、后拉、L2、失联 |
| 休眠 | nSLEEP = 0 | 两片 nSLEEP 拉低，CCR 清零 | 上电初始化、故障 |

### 4.4 上层控制完全复用

chassis.c 只调用 Motor_SetDuty / Motor_BrakeAll / Motor_CoastAll 等接口，不关心底层是 TB6612 还是 DRV8833，所以上电、油门、差速、刹车、失联恢复逻辑一行未改。

底盘控制状态机（与 TB6612 版相同）。

### 4.5 调试串口

debug.c 改为引用 huart3，状态帧格式不变：

### 5.3 故障排查

**表 5-3 故障排查**

| 现象 | 可能原因 | 处理 |

## 6 与 TB6612 版的迁移

如果同一辆车要从 TB6612 换成 DRV8833，只需要改三处：

- 接线：每个电机的两根方向线改接两路 PWM；STBY 改成 nSLEEP；
- CubeMX：增加 TIM1 四路 PWM，USART1 改成 USART3，PB3/PB9 设为输出；
- 代码：替换 motor.c / motor.h / board_pins.h / main.c / debug.c，其余模块直接复用。

反过来，从 DRV8833 换回 TB6612 也是同样三步。两版的上层参数（CFG_MAX_SPEED、刹车减速、舵机安全位）完全通用。

本版源码已用 STM32CubeIDE 2.2.0 自带的 arm-none-eabi-gcc 做过全量编译与链接，Flash 约 18.5 KB、RAM 约 2.4 KB，均可放入 STM32F103C8T6。
