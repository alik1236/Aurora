## 一、项目概览

Aurora 为 4 轮麦克纳姆轮全向移动小车：STM32F103C8T6 主控 + 2×L298N 电机驱动 + PS2 无线手柄遥控，配机械抓取机构（结构 2.0）与毛刷清扫收纳模块。中期考核 2026-10-19 24:00（完成度 40% + 规则测评 30% + 文档 30%）。

## 二、功能板块

### 底盘与四驱运动控制

**功能描述**

4 轮金属底盘 + 60mm 麦克纳姆轮 + TT 马达（1:48）×4，麦轮全向布局（轮距半宽/半长 L=W=60mm，k=L+W=120mm）。电机驱动采用 **2×L298N**（每块双通道）：ENA/ENB 跳线帽保持短接（常高），由 TIM3 四路 PWM 直接驱动 IN1/IN2、IN3/IN4 做**双 PWM**——一路 PWM、另一路低为前进，反之为后退，两路全高为刹车；同侧两路 IN 并联，两片模块分别驱动左右两侧；供电 VS=7.4V、VSS=5V、GND 与核心板共地（L298N 压降约 2V，马达端电压≈5.4V）。麦轮逆解公式：

```
FL = vx − vy − ω·k     FR = vx + vy + ω·k
RL = vx + vy − ω·k     RR = vx − vy + ω·k
```

**开发历程**

* **10-09 组装小车模型与电路，模块功能测试**：完成小车模型与电路组装（底盘、电机、主控、供电、机械臂等硬件装配与接线）。测试发现马达直接接电源转速仍很慢——排查方向：TT 马达为 1:48 减速电机空载转速本身偏低 → 电源电压是否达到额定（3–6V）→ 供电线路压降（杜邦线/接插件接触电阻）→ 马达个体质量问题。
* **10-11 引脚配置统一（底盘部分）**：核对芯片引脚配置与驱动模块接线，发现引脚配置与驱动模块不对应（原理图 V1.0 的 TB6612 占用引脚与 final.ioc 中电机 PWM 分配冲突）。确定两套完整接线定稿：DRV8833 版电机 PWM=PA0/PA8/PA9/PA10、方向=PA1/2/4/5；TB6612 版电机 PWM=TIM1 四通道 PA8~PA11、方向=PB4~PB7 + PB12~PB15。
* **10-12 底盘安装公差迭代整改**：执行端结构调试完成后整车总装，发现底盘车轮安装孔径公差不足，配件无法顺利装配。修改底盘建模参数，优化孔位直径与装配公差，重新打印底盘，完成整车基础结构适配。
* **10-14 测试马达控制：手柄无法控制马达转动**：对马达控制进行实机测试，发现手柄无法控制马达转动。排查线路，未发现异常；初步怀疑代码逻辑出错（待验证）。此问题进入持续排查期。
* **10-15 尝试改用其他驱动实验，马达控制问题依旧**：继续测试相关硬件，尝试改用其他驱动模块实验，手柄依然无法控制马达，问题未获解决。
* **10-18 新代码重写后马达可控；联合调试完成底座相关测试，达到完成标准**：使用 STM32CubeMX/STM32CubeIDE 重写的新代码重新搭建电路并测试，马达终于可以控制（突破性进展）。随后开展整车联合调试，完成底座相关测试（电机运动 / 底盘运动 / 遥控响应），达到本项功能完成标准。
* **10-19 联合调试，完成整车组装测试**：联合调试中完成整车组装测试，车体运动与遥控功能按完成标准验收通过。

### 机械抓取机构

**功能描述**

执行机构经多轮方案迭代（单钩 → 齿轮联动 → 平行连杆）后定稿为**结构 2.0**：借鉴龙门吊变幅连杆原理，多级连杆耦合将整机运动轴数缩减至 1 轴，实现 270° 超大有效摆动，配合夹爪完成抓取、收纳作业；与开源经典微型机械臂 MeArm 结构原理对标验证。

**开发历程**

* **10-01 结构方案初构思：钩子替代机械臂方案验证**：为简化执行机构，尝试单钩抓取结构替代常规机械臂并完成初步建模。结构推演与运动副统计后发现：钩子结构未减少整体运动轴数，自由度与原方案持平，减重与简化效果不明显，方案优化空间有限。
* **10-02 齿轮联动减自由度优化设计**：利用齿轮联动串联单个运动关节，机械联动耦合替代独立舵机控制，减少整机冗余自由度、精简驱动结构、降低电控负担，完成初步方案设计。
* **10-03 首轮打印测试：齿轮啮合精度问题暴露**：按初始参数 3D 打印装配测试。因初始齿轮模数过小、受打印机成型精度与层纹误差影响，齿形精度不足、配合间隙异常，出现卡顿、虚齿、打滑，联动结构无法正常工作，需整体参数迭代。
* **10-04 齿轮参数迭代升级**：齿轮模数统一调整为 2，增大齿厚与齿根强度，提升容错性与传动稳定性，规避低模数打印精度不足导致的传动失效。
* **10-05 借鉴平行连杆机构，重构执行端结构**：发现平行四连杆结构运动平稳、无偏摆、负载均匀、结构紧凑，适配抓取/收纳需求，放弃齿轮联动方案，基于平行杆原理开展全新结构建模。
* **10-06 手动建模打印，暴露连杆干涉问题**：独立三小时完成建模、切片与整机打印装配。连杆初始间距过小，运动行程受限于固定螺杆结构，运动被硬性限位，可用自由度大幅缩减，无法实现预设摆动/收纳动作。
* **10-07 连杆结构全方位参数优化**：增设沉头螺丝孔结构、增大主轴轴径、拓宽连杆配合间距、替换低突出度平头螺丝，消除螺丝凸起干涉、连杆剐蹭、行程受限，保证运动顺畅无卡顿。
* **10-08 舵机安装位置迭代修正**：原舵机安装孔位偏高导致连杆初始姿态偏移、运动力臂不合理。修改孔位参数、调整舵机安装高度、重新打印配件，完成结构对位校准。
* **10-09 成品对标参考，确认结构原型类别**：整车初代模型搭建完成后查阅开源机械结构资料，发现本队自主迭代的多连杆机械臂结构与开源经典微型机械臂 MeArm 原理高度相似，验证设计合理性与可行性。
* **10-10 龙门吊结构启发，单轴超大角度机构突破**：借鉴龙门吊垃圾车起重变幅连杆原理重构执行机构，多级连杆耦合设计将整机运动轴数缩减至 1 轴。调试发现基础平行二连杆在共线位置易错位、死点卡顿，新增第三限位连杆并调整安装夹角与配合位置，彻底规避死点错位，实现 270° 超大有效摆动。
* **10-11 孔位公差优化，解决摩擦卡顿问题**：新一轮打印装配后发现模型预留公差过小、轴孔配合过紧、摩擦阻力过大，螺丝限位结构过度锁死连杆行程。重新优化建模，放大配合间隙、优化限位结构，消除摩擦干涉。
* **10-13 完成 2.0 版本结构迭代，交付电控调试**：经多轮结构试错、参数优化、重打整改，完成整车机械结构 2.0 迭代版本，结构稳定、运动流畅、自由度达标，交付电控组开展程序调试与动作标定。
* **10-18 第一个舵机测试，暂未实现舵机标准**：联合调试中开展第一个舵机测试，初步验证舵机通电与信号控制，但尚未达到舵机运动相关完成标准（转动范围 / 稳定性未达标），待继续调试。
* **10-19 实现舵机控制**：联合调试中实现舵机控制，舵机运动达到完成标准，配合整车组装测试验收通过。

### PS2 无线遥控

**功能描述**

PS2 无线手柄（2.4G）遥控：软件模拟 SPI 时序（GPIO 位带模拟，不占用硬件 SPI），9 字节轮询读取，可对频锁定款手柄。引脚：DAT=PB12（输入上拉）、CMD=PB13、CS（即 ATT）=PB14、CLK=PB15；接收器为 6 针（无 ACK 脚）；9 字节轮询请求为 `01 42 00×7`。

**开发历程**

* **10-09 PS2 遥控接收模块暂未测试**：接收模块测试延后；测试时需确认手柄为锁定款并验证对频稳定。
* **10-11 引脚分配统一（PS2 部分）**：原理图 V1.0 未给 PS2 预留引脚，与 final.ioc 的 PB12~PB15 分配冲突；两套定稿均明确 PS2=PB12~PB15（位带），原理图需按定稿补齐。

* **10-13 代码修改后 PS2 配对问题解决**：接续前日测试，从代码层面修改（引脚时序/初始化配置）后，PS2 手柄与接收器配对成功，遥控链路打通。

### 固件实现（最终版）

> 工程位置：`firmware/ps2_car_arm_hal/`（STM32CubeIDE + HAL，STM32F103C8T6）
> 本节说明"最终做成了什么、为什么这样做"，与上面的开发历程对应。

**引脚分配**

| 功能 | 引脚 | 外设/模式 |
| --- | --- | --- |
| 左电机 IN1 / IN2 | PA6 / PA7 | TIM3_CH1 / CH2，1kHz PWM |
| 右电机 IN3 / IN4 | PB0 / PB1 | TIM3_CH3 / CH4，1kHz PWM |
| 夹爪舵机 | PA0 | TIM2_CH1，50Hz |
| 备用舵机 1~3 | PA8 / PA9 / PA10 | TIM1_CH1~CH3，50Hz |
| 关节 1 / 关节 2 | PB6 / PB7 | TIM4_CH1 / CH2，50Hz |
| 转台 / 铲斗 | PB8 / PB9 | TIM4_CH3 / CH4，50Hz |
| PS2 DAT / CMD / CS / CLK | PB12 / PB13 / PB14 / PB15 | GPIO 软件模拟 SPI |
| 状态 LED | PC13 | GPIO 输出（低电平点亮） |

**时钟与定时器**

| 项目 | 参数 | 结果 |
| --- | --- | --- |
| 系统时钟 | HSE 8MHz × PLL9 | 72MHz，APB1 /2 = 36MHz（定时器时钟 72MHz） |
| TIM3（电机） | PSC=71，ARR=999 | **1kHz**，占空比 0~999 对应 0~100% |
| TIM1 / TIM2 / TIM4（舵机） | PSC=71，ARR=19999 | **50Hz**，比较值 500~2500 对应 0.5~2.5ms |

**关键设计取舍（为什么这样做）**

1. **L298N + 双 PWM**：ENA/ENB 常高、只用 IN 脚调速，一根引脚既能定方向又能调速；相比"EN 调速 + 两个方向脚"，**每个电机少占 1 个 GPIO**，四路电机正好用完 TIM3 的四个通道。代价是每个电机需要 2 路互补 PWM，软件要保证两路不会同时输出高电平（否则直通）。
2. **PS2 用软件模拟 SPI**：硬件 SPI 的 SCK/MOSI 被电机 PWM 占用，软件位带更灵活；9 字节轮询在 72MHz 下约 0.5ms，10ms 周期余量充足。
3. **10ms 控制周期 + 速度斜坡**：每 10ms 速度最多变化 100/1000，避免摇杆猛推导致电流冲击、轮胎打滑和电池欠压复位。
4. **失联保护**：200ms 收不到有效帧即目标速度清零，底盘刹车；LED 快闪提示。
5. **舵机 50Hz + 1µs 分辨率**：500~2500µs 覆盖 0~180°，六个舵机分别占用 TIM1/2/4 的独立通道，互不影响。

**电机双 PWM（motor.c）**

```c
static void motor_left(int16_t speed)
{
    uint32_t duty;

    if (speed > 0) {                    /* 前进：IN1 = PWM，IN2 = 低 */
        duty = speed_to_duty(speed);
        __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, duty);
        __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_2, 0U);
    } else if (speed < 0) {             /* 后退：IN1 = 低，IN2 = PWM */
        duty = speed_to_duty(speed);
        __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, 0U);
        __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_2, duty);
    } else {                            /* 停止：两路全高，短路刹车 */
        __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, MOTOR_BRAKE_DUTY);
        __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_2, MOTOR_BRAKE_DUTY);
    }
}
```

**PS2 位时序（ps2.c）**

```c
for (i = 0U; i < 8U; i++) {
    if ((cmd & 0x01U) != 0U) { CMD_HIGH(); } else { CMD_LOW(); }
    cmd >>= 1;

    ps2_delay_us(PS2_HALF_PERIOD_US);   /* 2us，约 150kHz */
    CLK_LOW();                          /* 下降沿：手柄移出数据位 */
    ps2_delay_us(PS2_HALF_PERIOD_US);
    CLK_HIGH();                         /* 上升沿：主机采样 */
    ps2_delay_us(1U);

    data >>= 1;
    if (DAT_READ()) { data |= 0x80U; }
}
```

**差速混控 + 斜坡（car.c）**

```c
int16_t throttle = stick_value(pad->ly);   /* 上推为正 */
int16_t steer    = stick_value(pad->lx);

int32_t l = throttle + steer;
int32_t r = throttle - steer;
int32_t m = max(1000, max(abs(l), abs(r)));  /* 超限时等比缩放，保留转向比例 */
if (m > 1000) { l = l * 1000 / m; r = r * 1000 / m; }

s_cur_left  = ramp_to(s_cur_left,  (int16_t)l, CAR_RAMP_STEP);
 s_cur_right = ramp_to(s_cur_right, (int16_t)r, CAR_RAMP_STEP);
Motor_Set(s_cur_left, s_cur_right);
```

### 问题根因与解决（复盘）

**PS2 配对失败（10-12 ~ 10-13）**

- 现象：接收器与手柄对不上码；换供电、换接线、按对码键均无效。
- 根因：**初始化序列不完整**。旧代码只发送 `01 43 00 01`（进入配置模式）+ 7 个 `00`，
  没有发送 `44`（设置模拟模式）和退出序列 `43 00 00 5A 5A 5A 5A 5A`，手柄停在配置模式，
  返回的不是正常按键帧。
- 解决：补全 **enter → mode(0x44) → exit** 三步，上电后先等 300ms 再初始化；配对恢复正常。

**手柄无法控制马达（10-14 ~ 10-18）**

- 现象：手柄可配对，但推杆、按键电机无反应；换驱动模块、换核心板均无效。
- 排查顺序：接线通断 → 更换驱动模块 → 更换核心板 → 重写代码。
- 根因（两条叠加）：
  1. **引脚分配与实物不对应**：原理图 V1.0 按 TB6612 设计，实物改 L298N 后引脚未同步；
  2. **PS2 数据帧不可信**：初始化序列不完整，即使引脚对上，按键/摇杆值仍异常。
- 解决：按最终接线重定引脚（PA6/PA7、PB0/PB1、PB12~PB15），重写 PS2 初始化与 9 字节轮询；
  10-18 新固件下马达可控（见「固件实现（最终版）」）。

### 驱动方案选型对比

| 方案 | 每片通道 | 调速方式 | 每电机占用引脚 | 优点 | 局限 | 结果 |
| --- | --- | --- | --- | --- | --- | --- |
| DRV8833 | 2 | 双 PWM | 2 | 体积小、效率高、3.3V 逻辑兼容 | 单通道电流偏小，四电机需两片；模块易损 | 早期方案，10-15 后弃用 |
| TB6612 | 2 | PWM + 方向 | 3（PWM + IN1/IN2） | 效率高、带待机脚 | 需 STBY，引脚更多；与原理图 V1.0 绑定 | 未落地 |
| **L298N** | 2 | **双 PWM（IN 脚）** | **2** | 便宜、耐压高、双 PWM 省引脚、抗堵转 | 压降约 2V，需散热片 | **最终方案（2 片）** |

> 选型结论：四路电机 + 引脚紧张 + 成本上限 400 元，L298N 的双 PWM 接法每电机只占 2 个引脚，
> 正好用满 TIM3 四个通道；DRV8833 电流余量不足，TB6612 需要额外的 STBY 与方向脚。

**功能描述**

**开发历程**
